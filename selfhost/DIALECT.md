# The selfhost dialect

This is the exact Pascal subset that the self-hosted compiler (`selfhost/`) may
be written in. It is milestone S0 of [SELFHOST.md](../SELFHOST.md).

**The rule:** every source file must compile and behave the same under both
compilers below. Anything not listed here is not allowed.

| Compiler | Command |
|----------|---------|
| pcc (the target) | `pcc --mode=tp -I selfhost` |
| Free Pascal 3.2.2 (the reference) | `fpc -Mobjfpc -Sh- -Cr -Co` |

Free Pascal is the second compiler for three reasons:

- It proves the dialect is real Pascal with one meaning.
- The port (S3–S8) can be developed and tested with FPC before pcc supports
  every feature, so S1 and the port can overlap.
- It gives a second, independent bootstrap path: pcc built by FPC must produce
  the same IR as pcc built by pcc.

`utils/selfhost-lint.py` checks the mechanical rules (comment contents,
banned identifiers); the lit test `tests/selfhost/lexer.test` runs it.

The executable form of this spec is `selfhost/dialect/`. It holds eight check
programs with `.expected` output generated by FPC; run it with
`run.sh fpc` or `run.sh pcc`. Both pass 8/8 since S1 (2026-11-06); before
S1, pcc passed 0/8. The lit test `tests/run/dialect.test` runs the checks
with pcc.

## 1. Program structure

- **Units:** one program file (`pcc.pas`) plus units, one unit per file. The
  file name is the unit name in lower case (`pclex.pas`).
- **Unit graph:** `uses` appears only in the interface section, and the unit
  graph is acyclic.
- **Unit sections:** `interface`, `implementation`, and optionally
  `initialization`. There is no `finalization`.
- **Include files:** `{$I name.inc}` may be used, for example for tables
  generated from `TokenKinds.def`. Include files hold only declarations.
- **Directives:** the only directives allowed are `{$I file}` and the paired
  local check switches `{$R-}`/`{$R+}` and `{$Q-}`/`{$Q+}` (section 6).
  There is no `{$mode}`, `{$H}`, `{$ifdef}` or any other directive. The mode
  is set on the command line.
- **Comments:** `{ }` and `//`. A comment must not contain `{`, `}`, `(*` or
  `*)`. FPC's objfpc mode nests `{ }` comments and TP mode does not, so text
  such as `{ see {$R-} }` parses differently in the two compilers.
- **Program header:** `program pcc;` with no program parameters.

## 2. Types

| Use | Allowed types |
|-----|---------------|
| Integers | `longint` (32-bit, the default choice), `int64`, `cardinal` (unsigned 32-bit, for hashes), `byte`, `word`, `shortint`, `smallint` |
| Not allowed | `integer` (16-bit in FPC's TP mode, 32-bit in pcc), `qword`, `nativeint`, `sizeint` |
| Others | `boolean`, `char` (8-bit), `double`, enumerations, subranges, records and variant records, arrays, `set of` an enumeration or `char`, pointers `^T`, `pointer`, `pchar` (only at the C boundary), `string` and `string[N]` (short strings), procedural types |
| Not allowed | `real`, `extended`, `ansistring`, dynamic arrays, `file`/`text`, objects and classes, `packed`, generics |

More rules:

- **Mixing signed and unsigned:** never mix signed and unsigned operands in
  one expression without a typecast. FPC widens `longint op cardinal` to
  `int64`. pcc must match it, but the dialect does not rely on it.
- **`int64` arithmetic:** mixing `int64` with smaller signed types widens to
  `int64`, in both compilers.
- **Shifts:** `shr` is a logical shift. Shift only non-negative values or
  unsigned types.
- **Floating point:** no real operation may overflow or be invalid at run
  time: Free Pascal enables FPU exception traps, so it stops with "Runtime
  error 207" where pcc yields infinity. Build infinities from their bits
  (`sysInfinity`) and check magnitudes before calling C (`strtod`).
- **Overflow:** no operation may overflow outside a `{$Q-}` region. pcc
  checks every operation, while FPC skips some (`sqr` wraps silently), so
  only code that never overflows behaves the same in both.
- **Sizes and layout:** `sizeof` is used only to allocate memory. Code must
  not depend on record layout, padding or alignment, and records are never
  written to files.
- **`trunc` and `round`** return `int64`.

## 3. Declarations and routines

- **Allowed:** `const`, `type` and `var` sections in any order;
  forward-declared routines; nested routines that access outer locals.
- **Parameter kinds:** value, `var` and `const`. `const` is used for every
  string and record parameter that is not modified. There are no untyped
  parameters (`var x` without a type) except in the built-ins
  `fillchar`/`move`, and no default parameter values or overloading.
- **Function results:** assign to the function name. `Result` is not used,
  and there is no local or parameter named `result`. Functions may return
  simple types, pointers, strings and records (not arrays); a record
  result can be selected from directly (`makeRange(a, b).e`).
- **Typed constants:** they are read-only (objfpc allows writing them, pcc
  does not). They may be arrays (including indexed by an enumeration) and
  records, including arrays of records.
- **Procedural types:** `type TVisit = procedure(k: TTokKind);`. Assign with
  `v := @routine`, call with `v(x)`, test with `assigned(v)`, and clear with
  `v := nil`. Only global (non-nested) routines may be assigned.
  Procedural types always take at least one parameter: a bare name `f` of
  a parameterless procedural variable is a call in pcc but the value itself
  in FPC's objfpc mode.
- **External C functions:** `function c_strlen(s: pchar): int64; cdecl;
  external 'c' name 'strlen';`
  - Names start with `c_`, and all of them live in the unit `pcsys`.
  - Parameter and result types are limited to `longint`, `int64` (for
    `size_t`/`long`), `double`, `pointer` and `pchar`. There are no `var`
    parameters, records passed by value, callbacks or varargs.
  - A string literal may be passed directly as a `pchar` argument. A string
    variable is passed as `@s[1]` after appending `#0`.

## 4. Statements and expressions

- **Allowed statements:** assignment, `if`, `case` (with `else`), `while`,
  `repeat`, `for` (`to`/`downto`), compound statements, procedure calls, and
  function calls used as statements.
- **Control transfer:** `break`, `continue`, `exit` and `exit(value)`.
  `halt(code)` is allowed only in the driver.
- **Not allowed:** `goto`/`label`, `with`, and assigning to a `for` loop
  variable or using it after the loop.
- **Boolean operators:** `and` and `or` short-circuit, and code relies on it:
  `(p <> nil) and (p^.x = 1)`.
- **Order of evaluation:** code must not depend on the order in which
  arguments or operands are evaluated.
- **Typecasts:** `T(expr)` between ordinal types, including enumerations,
  `char` and the integer types, and between pointer types. Casts are not
  range-checked. A value typecast between a record and an integer, or between
  `double` and an integer, is not allowed; reinterpret bits with a variant
  record instead (section 5).
- **Built-ins:**
  - Arithmetic and ordinals: `ord chr succ pred odd abs inc dec low high
    sizeof trunc round`.
  - Strings: `length copy pos delete insert upcase concat`.
  - Memory: `new dispose getmem freemem reallocmem fillchar move`.
  - Other: `assigned paramcount paramstr halt`.
  - Forms: only the procedure forms `getmem(p, n)` and `freemem(p)`.
    `reallocmem(p, n)` on `nil` allocates.
- **Pointer arithmetic:** none, and no `pchar` indexing. Index a pointer to a
  large array type instead (section 5).
- **Untyped pointers** are never dereferenced: cast first,
  `fillchar(PCharArray(p)^, n, 0)` (FPC accepts `p^`, pcc does not).

## 5. Idioms the dialect relies on

**Open-ended arrays (L4).** A pointer to an array type larger than any real
allocation, indexed inside `{$R-}`:

```pascal
type
  TPtrArray = array[0..$FFFFFFF] of pointer;
  PPtrArray = ^TPtrArray;
...
  reallocmem(l.items, l.cap * sizeof(pointer));
  {$R-} l.items^[l.count] := p; {$R+}
```

Variables of these array types are never declared; they exist only behind
pointers.

**Reading a double's bits (L9).** A variant record with an untagged
`case boolean of` overlay of `double` and `int64`.

**Strings for C.** `s := s + #0; c_fopen(@s[1], 'rb')`. Text longer than 254
characters (source files, IR output) never lives in a `string`. It lives in
heap buffers managed by `pcutil`.

## 6. Run-time checks

Range and overflow checks stay **on** for the whole compiler. They are
switched off only around the code that needs it, with a matching `+`:

- `{$Q-}`/`{$Q+}` around hashing and other deliberate wrap-around;
- `{$R-}`/`{$R+}` around open-ended array accesses and hashing.

## 7. Input and output

The compiler does **no Pascal I/O**: no `write`, `writeln`, `read`,
`assign` or `text` files. All I/O goes through `pcsys`, which wraps the C
library: `fopen`, `fread`, `fwrite`, `fclose`, `fdopen(1/2)` for
stdout/stderr, `getenv`, `system`, `remove` and `strtod`. This has several
benefits:

- There is one buffered output path, so stdout and stderr interleave
  correctly.
- The pcc runtime needs no new file built-ins.
- Process execution and real-number parsing come for free.

The dialect check programs use `writeln` only to report results.

## 8. Names

Pascal identifiers are case-insensitive, so names must stay distinct when
case is ignored.

| Kind | Convention | Example |
|------|------------|---------|
| Types | `T` + PascalCase | `TToken`, `TTypeKind` |
| Pointer types | `P` + the name | `PNode` |
| Enumeration values | lower-case prefix per enumeration | `tkIdent`, `nkBinary`, `skVar` |
| Routines, variables and fields | camelCase | |
| Constants | camelCase | `maxErrors` |
| C imports | `c_` + the C name | `c_fopen` |

Further rules:

- No identifier may equal a type name, unit name or routine name visible
  in the same scope when case is ignored.
- Names must not shadow System routines (`length`, `copy`, `move`, `pos`,
  `str`, `val`, `exit`, `halt`, `assigned`, …).
- Reserved words of either compiler are never used as identifiers. FPC's
  objfpc mode adds `as class except exports finally initialization
  finalization inherited is library on operator out property raise
  resourcestring threadvar try`, and pcc's TP mode adds `inline asm object
  constructor destructor shl shr xor string unit interface implementation
  uses`.

**Dropped from SELFHOST.md part A by this spec:**

- **L6** (named Pascal files), **L8** (`str`/`val`) and **L11** (subprocesses)
  are covered by C calls (section 7) plus small routines in `pcutil`.
- **R1** (dynamic arrays) is replaced by the open-ended-array idiom.
  Dynamic arrays are reference-counted in FPC, so a simpler pcc version would
  behave differently.
